AVPM : 04.01. Функциональная спецификация

Created by Перейти, last modified on нояб. 14, 2026

Общая информация

Модуль предназначен для подготовки и согласования устава проекта. Пользователь заполняет сведения, задает согласующих и отправляет документ по последовательному маршруту. После последнего положительного решения устав становится утвержденным.

Страницы модуля: реестр /project-charters и карточка /project-charters/{id}. Предварительно выбирать активный проект не требуется.

Доступность

Пользователь должен быть авторизован. Действия определяются разрешениями его роли:

Действие

Разрешение

Открыть реестр/карточку, посмотреть историю, добавить комментарий

project_charter:access

Создать или изменить устав

project_charter:manage

Отправить, согласовать или отклонить

project_charter:approve

Создать проект из устава

project:create

Для действий через интерфейс также нужен доступ к странице. Согласовать или отклонить шаг может только назначенный на него пользователь. Отдельной проверки принадлежности к организации/проекту в API уставов нет.

Особенности и ограничения

  • Статусы устава: Черновик, На согласовании, Утвержден, Отклонен.

  • Редактирование разрешено в любом статусе. Оно возвращает устав в черновик и заменяет маршрут. Повторно отправить можно любой устав, кроме уже находящегося на согласовании.

  • Бюджет равен сумме статей. API допускает общий бюджет без статей. Стандартная форма требует заполнить хотя бы одну статью, один этап и одного согласующего.

  • При выборе шаблона документы его нормативных требований добавляются автоматически. Показатель «Покрыто требований» означает наличие ссылок на документы, а не выполнение требований.

  • История доступна только для просмотра. Автоматических почтовых уведомлений о согласовании в этих командах нет.

Сценарии использования

UC-1. Просмотр реестра и карточки

Предусловие: у пользователя есть доступ к уставам.

Точка входа: меню или адрес реестра.

Действие пользователя

Реакция системы

Открывает реестр

Вызывает GET /api/project-charters с page=1, pageSize=100. Показывает название, проект, статус, версию, ответственного, бюджет и дату обновления. Над таблицей отображает количество уставов и суммарный бюджет загруженного набора.

Вводит поиск или выбирает фильтры

Повторяет запрос с поиском, статусом, ID проекта и/или ответственного. Поиск выполняется по названию и цели устава, названию проекта и организации. Таблица показывает по 10 строк из загруженных результатов.

Нажимает «Открыть карточку»

Вызывает GET /api/project-charters/{id}, загружает маршрут, журнал, версии и комментарии. Показывает сведения устава и доступные действия. Если проект уже связан, устанавливает его активным в клиентском контексте.

Альтернативный сценарий: если по выбранным фильтрам уставы не найдены, система показывает сообщение «По текущим фильтрам уставы не найдены».

Ошибки: при сбое загрузки система показывает сообщение об ошибке реестра или карточки. При отсутствии права доступа страница показывает уведомление об ограничении доступа.

UC-2. Создание устава

Предусловия: у пользователя есть право на создание уставов, необходимые справочники доступны.

Точка входа: кнопка «Создать устав» в реестре.

Действие пользователя

Реакция системы

Нажимает «Создать устав»

Открывает форму. Загружает организации, пользователей и доступные справочники проектов, шаблонов и нормативных документов.

Заполняет сведения и маршрут

Проверяет обязательные поля, показывает итог бюджета. Позволяет добавлять и удалять строки бюджета, этапов, нормативных ссылок и согласующих. Порядок согласования соответствует порядку строк.

Нажимает «Сохранить»

Передает POST /api/project-charters. Проверяет значения и существование связанных записей. Дополняет нормативные ссылки документами требований выбранного шаблона. Создает черновик версии 1, сохраняет снимок и событие создания.

Получает подтверждение

При ответе 201 показывает «Устав проекта создан», закрывает форму и открывает карточку.

Состав формы:

Раздел

Что заполняет пользователь

Основные данные

Обязательные поля: организация, название, цель и бизнес-обоснование.

Необязательные: проект, шаблон и ответственный.

Бюджет

Обязательные поля: категория, название и неотрицательная сумма каждой статьи.

Необязательные: примечание.

Этапы

Обязательные поля: название этапа.

Необязательные: плановая дата и описание.

Нормативные ссылки

Обязательные поля: документ.

Необязательные: пункт и примечание.

Пустые строки не отправляются.

Маршрут

Обязательные поля: согласующий на каждом шаге.

Необязательные: название шага.

Ошибки: незаполненные поля отмечаются в форме, запрос не выполняется. При отказе API система показывает описание ошибки, форма остается открыта для исправления.

UC-3. Изменение устава

Предусловия: карточка открыта, у пользователя есть право изменения.

Точка входа: кнопка «Редактировать».

Действие пользователя

Реакция системы

Нажимает «Редактировать»

Показывает ту же форму с текущими данными.

Меняет сведения и сохраняет

Вызывает PUT /api/project-charters/{id}, передавая полный состав формы. Заменяет статьи бюджета, этапы, нормативные ссылки и маршрут. Устанавливает статус «Черновик», сбрасывает решения шагов, увеличивает версию и сохраняет историю изменения.

Получает подтверждение

Показывает «Устав обновлен» и возвращается к просмотру обновленной карточки.

Альтернативные сценарии: кнопка «Отменить редактирование» возвращает к карточке без сохранения. При ошибке API форма остается в режиме редактирования. Для исправленного отклоненного устава далее выполняется UC-4.

Альтернативный сценарий: при нажатии кнопки «Отменить редактирование» система возвращает пользователя к карточке без сохранения изменений.

Ошибки: при ошибке API форма остается в режиме редактирования и сохраняет введенные сведения.

После исправления отклоненного устава пользователь может повторно отправить его на согласование по UC-4.

UC-4. Отправка на согласование

Предусловия: наличие хотя бы одного шага согласования, статус заявки отличается от «На согласовании» или «Утвержден», у пользователя есть право на отправку заявки на согласование.

Точка входа: кнопка «Отправить на согласование».

Действие пользователя

Реакция системы

Нажимает «Отправить на согласование»

Открывает диалог с обязательным комментарием.

Вводит комментарий и подтверждает

Вызывает POST /api/project-charters/{id}/submit, тело: {"comment":"Готово к согласованию"}. Проверяет комментарий, наличие маршрута и статус. Сбрасывает прежние решения, активирует первый шаг и переводит устав в «На согласовании». Сохраняет новую версию и записи журнала.

Получает результат

При 200 показывает «Устав отправлен на согласование», обновляет статус и маршрут.

Ошибки: пустой комментарий, отсутствие шагов согласования или повторная отправка устава со статусом «На согласовании». Состояние устава не изменяется, система показывает сообщение об ошибке от сервера. После получения ответа API диалог закрывается независимо от результата. Для повторной отправки необходимо открыть диалог заново.

UC-5. Согласование шага

Предусловия: устав на согласовании, текущий шаг назначен пользователю с правом согласования.

Точка входа: кнопка «Утвердить шаг».

Действие пользователя

Реакция системы

Нажимает «Утвердить шаг»

Открывает диалог с необязательным комментарием.

Подтверждает решение

Вызывает POST /api/project-charters/{id}/approve. Проверяет состояние устава и назначение согласующего. Завершает текущий шаг, сохраняет решение, дату и новую версию.

Получает результат

Если есть следующий шаг, активирует его, устав остается «На согласовании». Если это последний шаг, переводит устав в «Утвержден». Показывает «Шаг согласования утвержден» и обновляет карточку.

Ошибки: пользователь не назначен согласующим, отсутствие активного шага согласования или неподходящий статус устава. Сервер возвращает ошибку 400 с сообщением, данные остаются без изменений. Кнопки согласования доступны всем пользователям с общим правом согласования, но сервер дополнительно проверяет назначение пользователя на текущий шаг.

UC-6. Отклонение устава

Предусловия: устав находится на согласовании, текущий шаг назначен пользователю с правом согласования.

Точка входа: кнопка «Отклонить».

Действие пользователя

Реакция системы

Нажимает «Отклонить»

Открывает диалог с обязательной причиной.

Заполняет причину и подтверждает

Вызывает POST /api/project-charters/{id}/reject, тело: {"reason":"Уточнить бюджет"}. Проверяет причину, состояние и назначение согласующего. Помечает шаг и устав как отклоненные, сохраняет новую версию и событие журнала.

Получает результат

Показывает «Устав отклонен» и причину в маршруте/журнале. Следующий шаг не запускается.

Ошибки: отсутствие причины отклонения или невыполнение условий согласования. Система отклоняет запрос без изменения данных.

После отклонения пользователь может отредактировать устав по UC-3 и повторно отправить его на согласование по UC-4.

UC-7. Просмотр истории

Предусловие: открыта карточка устава.

Действие пользователя

Реакция системы

Просматривает маршрут, журнал и версии

Загружает маршрут согласования, журнал действий и историю версий устава. Отображает шаги маршрута в порядке согласования, а записи журнала и версии устава сортирует от новых к старым.

Нажимает «Открыть версию»

Загружает выбранную версию устава и открывает ее в отдельном окне. Отображает сохраненные основные сведения, бюджет, этапы, документы и маршрут согласования. Текущая версия устава остается без изменений.

Альтернативный сценарий: если сохраненные данные версии отсутствуют, кнопка «Открыть версию» недоступна.

Ошибки: если системе не удалось загрузить выбранную версию, в окне отображается сообщение «Данные версии не найдены». Восстановление предыдущих версий не предусмотрено.

UC-8. Добавление комментария

Предусловие: карточка устава открыта в режиме просмотра. Право на редактирование устава не требуется.

Действие пользователя

Реакция системы

Вводит текст и нажимает «Добавить комментарий»

Проверяет, что текст не пустой, вызывает POST /api/project-charters/{id}/comments, тело: {"text":"Уточнить план испытаний"}. Сохраняет текст, автора, дату и событие журнала.

Получает подтверждение

Показывает «Комментарий добавлен», очищает поле и обновляет обсуждение. Версия, статус и дата обновления устава не меняются.

Ошибки: если текст комментария пустой, система показывает предупреждение и не отправляет запрос. При ошибке API введенный текст сохраняется в поле, система отображает сообщение об ошибке.

UC-9. Создание или открытие проекта

Предусловие: устав имеет статус «Утвержден», связанный проект отсутствует, у пользователя есть право на создание проекта (project:create).

Действие пользователя

Реакция системы

Нажимает «Создать проект» в реестре/карточке

Вызывает POST /api/project-charters/{id}/create-project. Проверяет утверждение и отсутствие связанного проекта. Создает проект с названием устава и целью в описании; назначает менеджером ответственного либо инициатора команды.

Ожидает завершения

Если выбран шаблон, проверяет его публикацию и архивность, создает доску и применяет структуру. Без шаблона этот сервис доску не создает. Сохраняет связь проекта с уставом.

Получает результат

При 201 показывает успех, выбирает созданный проект и открывает /dashboard. Версия устава при этом не увеличивается.

Нажимает «Открыть проект», если он уже связан

Выбирает связанный проект и открывает /dashboard без команды создания. Доступ к данным проекта проверяется его API.

Ошибки: устав не утвержден, проект уже связан с уставом или выбранный шаблон недоступен. Система показывает сообщение об ошибке и не выполняет переход. При ошибке создания проекта система отменяет все изменения в рамках транзакции.
