AVPM : 04.02. Функциональная спецификация

Created by Перейти, last modified on нояб. 14, 2026

Общая информация

Модуль предназначен для создания проектов из утвержденных уставов, выбора активного проекта и управления составом сотрудников.

Основные точки входа: каталог проектов /project-select, карточка устава /project-charters/{id} и каталог досок /dashboard.

Каталог проектов и уставы доступны без предварительного выбора активного проекта.

Доступность

Все серверные методы требуют авторизации через JWT. Система отдельно проверяет права пользователя и его роль внутри проекта.

Действие

Условия доступа

Просмотр каталога проектов

Право project:access. Без project:create доступны только проекты, в которых состоит пользователь

Просмотр проекта, участников и досок

Право project:access и членство в проекте либо право project:create

Создание проекта из устава

Право project:create. Для создания через карточку также необходим доступ к уставам

Просмотр кандидатов и изменение состава сотрудников

Право project:access и роль manager в проекте

Изменение сведений о проекте

Право project:update

Удаление проекта

Право project:delete

В проекте предусмотрены роли manager и member. Они не заменяют глобальные роли и права учетной записи.

Право project:create дает возможность просматривать проекты без членства в них, но не разрешает изменять состав сотрудников. Для управления сотрудниками необходима роль manager в конкретном проекте.

Особенности и ограничения

  1. Проект создается только из утвержденного устава, который еще не связан с проектом. Все сведения для создания система получает из устава.

  2. Менеджером проекта становится ответственный устава. Если ответственный не указан, система назначает пользователя, создавшего проект.

  3. При создании проекта без шаблона система сохраняет проект, назначает менеджера и связывает проект с уставом. Доска автоматически не создается.

  4. При наличии шаблона система создает доску и применяет структуру опубликованного неархивного шаблона.

  5. Сотрудники проекта, пользователи доски и исполнители задач хранятся отдельно. Изменение состава сотрудников проекта не обновляет участников досок и назначения задач.

  6. Активный проект хранится на стороне frontend в Redux и localStorage по ключу active_project_id. Отдельный API для выбора активного проекта отсутствует.

  7. Проект не имеет собственного статуса или признака архивирования. Метод DELETE физически удаляет проект, если связи в БД допускают удаление.

Сценарии использования

UC-1. Просмотр каталога и выбор проекта

Предусловия: пользователь авторизован и имеет право project:access.

Точка входа: страница /project-select или переключение проекта в основном меню.

Действие пользователя

Реакция системы

Открывает каталог проектов

Вызывает GET /api/projects, обычно с organizationId из клиентского контекста. Отображает название, организацию, описание, идентификатор и признак активного проекта. Карточки сортируются по названию.

Нажимает «Обновить список»

Повторно загружает каталог проектов. Если ранее выбранный проект отсутствует в полученном списке, очищает активный проект.

Нажимает «Открыть проект»

Сохраняет идентификатор проекта в Redux и localStorage. Выполняет переход на сохраненный адрес возврата или /dashboard. Отдельный запрос выбора проекта не отправляется.

Возвращается в приложение

Проверяет сохраненный идентификатор по списку доступных проектов. Если проект отсутствует, очищает выбранный идентификатор. Автоматический выбор первого проекта не выполняется.

Альтернативные сценарии: если доступные проекты отсутствуют, система отображает пустой каталог с пояснением о создании проекта или назначении пользователя менеджером.

При отсутствии активного проекта защищенные рабочие страницы перенаправляют пользователя в каталог проектов.

Ошибки: при отсутствии права project:access система показывает уведомление об ограничении доступа. При ошибке загрузки каталога отображается сообщение об ошибке. Ошибка первоначальной загрузки обрабатывается отдельно.

UC-2. Создание проекта из устава без шаблона

Предусловия: устав имеет статус «Утвержден», связанный проект отсутствует, у пользователя есть права project:create и доступа к карточке устава.

Точка входа: карточка утвержденного устава. В каталоге проектов кнопка «Создать проект» показывает пояснение и предлагает перейти к уставам.

Действие пользователя

Реакция системы

Открывает утвержденный устав

Отображает кнопку «Создать проект», если устав не связан с проектом. При отсутствии права создания кнопка недоступна.

Нажимает «Создать проект»

Вызывает POST /api/project-charters/{id}/create-project без тела запроса. Проверяет статус устава, отсутствие связанного проекта и наличие обязательных сведений: названия, цели, бизнес-обоснования и организации.

Ожидает завершения создания

В транзакции реляционной БД создает проект с организацией и названием из устава. Цель устава переносит в описание проекта. Назначает менеджера и сохраняет projectId в уставе. Доска не создается.

Получает подтверждение

При ответе 201 добавляет проект в клиентский каталог, делает его активным, показывает сообщение «Проект создан на основе утвержденного устава» и открывает /dashboard.

Ошибки: если устав не найден, сервер возвращает 404. Если устав не утвержден, уже связан с проектом или не содержит обязательных сведений, сервер возвращает 400 с полями code и message. Ошибки хранения могут иметь другой формат ответа.

При отказе пользователь остается в карточке устава. Если ошибка возникает до завершения транзакции, система отменяет изменения в реляционной БД.

Постусловия: проект создан и связан с уставом, менеджер назначен. Статус и версия устава остаются без изменений, новые записи в журнал согласования не добавляются.

При следующем открытии карточки доступна кнопка «Открыть проект». Открытие карточки связанного устава также делает его проект активным.

UC-3. Создание проекта с применением шаблона

Предусловия: условия UC-2 выполнены, в уставе выбран шаблон проекта.

Точка входа: кнопка «Создать проект» в карточке утвержденного устава.

Действие пользователя

Реакция системы

Нажимает «Создать проект»

Выполняет проверки и создание проекта по UC-2. Дополнительно проверяет, что выбранный шаблон существует, опубликован и не находится в архиве.

Ожидает создания структуры

Создает доску с названием проекта. Назначает владельцем и первым пользователем доски инициатора запроса. Стандартные колонки не добавляются, структура формируется по шаблону.

Получает результат

Применяет колонки, поля карточек, стартовые задачи, зависимости и этапы CRM. При наличии сведений в шаблоне создает базу знаний и записи соответствия требованиям. Возвращает идентификатор доски и счетчики применения. Интерфейс делает проект активным и открывает /dashboard.

Ограничения: создание базы знаний и записей соответствия требованиям включено в команду. Отдельные переключатели в интерфейсе отсутствуют.

Готовые отчетные формы не создаются. Поле appliedReportsCount имеет значение 0, а deferredReportsCount содержит количество отложенных форм из шаблона.

Ошибки: если шаблон удален, архивирован или не опубликован, сервер возвращает CHARTER_VALIDATION_FAILED. При ошибке применения шаблона система отменяет всю операцию в рамках текущей транзакции.

Постусловия: проект создан и связан с уставом, структура шаблона применена. Менеджер проекта и владелец доски могут быть разными пользователями.

UC-4. Изменение состава сотрудников проекта

Предусловия: у пользователя есть право project:access и роль manager в проекте.

Точка входа: кнопка «Настройки» на карточке проекта в каталоге.

Действие пользователя

Реакция системы

Открывает настройки проекта

Вызывает GET /api/projects/{projectId}/members и GET /api/projects/{projectId}/member-options. Отображает менеджеров отдельно от обычных сотрудников. Менеджеры исключаются из списка выбора сотрудников.

Выбирает или снимает сотрудников

Позволяет выбрать несколько пользователей. Список кандидатов формируется из всех учетных записей без фильтрации по организации.

Нажимает «Сохранить»

Вызывает PUT /api/projects/{projectId}/members с полным списком memberUserIds. Сервер сохраняет менеджеров, удаляет отсутствующих в списке сотрудников с ролью member и добавляет новых.

Получает подтверждение

При ответе 200 показывает сообщение «Состав сотрудников проекта обновлен», закрывает окно настроек и обновляет каталог.

Альтернативные сценарии: если пользователь передает пустой список, система удаляет всех обычных сотрудников, сохраняя менеджеров. Повторяющиеся идентификаторы объединяются, неположительные значения игнорируются.

Ошибки: если проект или выбранная учетная запись не найдены, сервер возвращает 404. Если пользователь не имеет роли manager, возвращается 403. При ошибке сохранения окно настроек остается открытым.

Особенности интерфейса: кнопка «Настройки» доступна и обычным участникам проекта. Сервер дополнительно проверяет права при загрузке кандидатов и сохранении изменений.

Метод не позволяет назначать или удалять менеджеров проекта.

UC-5. Открытие досок выбранного проекта

Предусловия: проект выбран и доступен пользователю для просмотра.

Точка входа: страница /dashboard.

Действие пользователя

Реакция системы

Открывает рабочую страницу

Вызывает GET /api/projects/{projectId}/boards для активного проекта. Загружает список досок с колонками без карточек задач.

Выбирает доску

Открывает выбранную доску через модуль «Канбан и задачи». Сведения о задачах загружаются отдельными методами API.

Переходит в другой проект

Обновляет идентификатор активного проекта через каталог. Последующие запросы досок используют новый идентификатор.

Альтернативные сценарии: если проект создан без шаблона, список досок может быть пустым. Создание досок описано в модуле «Канбан и задачи».

Ошибки: если проект не найден, сервер возвращает 404. Если пользователь не состоит в проекте и не имеет права project:create, возвращается 403.

Доступ к списку досок проекта не дает пользователю автоматического членства в каждой доске.

Операции, доступные через API

Помимо описанных пользовательских сценариев, backend поддерживает следующие методы:

Метод

Назначение

GET /api/projects/{id}

Получение карточки проекта с участниками

PUT /api/projects/{id}

Изменение организации, названия и описания проекта

DELETE /api/projects/{id}

Удаление проекта с учетом ограничений внешних ключей

Методы изменения и удаления проекта реализованы на backend, но отдельные формы для этих действий в текущем каталоге отсутствуют.

Метод DELETE не удаляет связанные доски предварительно. При наличии связей, запрещающих удаление проекта, БД отклоняет операцию. После успешного удаления ссылка на проект в уставе получает значение NULL.

Прямое создание проекта и создание проекта из шаблона недоступны. Для создания проекта используется утвержденный устав.
