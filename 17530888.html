AVPM : PUT /api/project-charters/{id}

Created by Екатерина Попова, last modified on нояб. 14, 2026

Изменяет данные устава и переводит его в статус draft.

Доступ: право project_charter:manage.

Используется в UC-3. Изменение устава.

Схема работы

Алгоритм

  1. Проверить совпадение идентификаторов устава в URL и теле запроса. Проверить обязательные поля, суммы и существование связанных записей по правилам создания устава.

  2. Найти устав по идентификатору. Редактирование разрешено при любом статусе устава.

  3. Обновить основные сведения, полностью заменить статьи бюджета, этапы, нормативные ссылки и маршрут согласования. Новым шагам присвоить статус waiting.

  4. Присвоить уставу статус draft, увеличить версию, сохранить его состояние в истории версий и добавить в журнал событие updated.

  5. Вернуть обновленную карточку устава.

Входные параметры

Параметр пути (PATH) и тело запроса (BODY, JSON).

Как при создании

Полный состав полей и правила проверки описаны в POST /api/project-charters

Метод полностью заменяет данные устава. Поэтому запрос должен содержать все сведения, которые необходимо сохранить.

Если массив не передан, система заменяет его пустым списком.

Ответ

200 OK: возвращает обновленную карточку устава со статусом draft.

Структура ответа совпадает с GET /api/project-charters/{id}.

Каждый успешный запрос увеличивает версию устава, включая повторную отправку тех же данных.

Ошибки

Код

Причина

400

Идентификаторы устава в URL и теле не совпадают, поля содержат некорректные значения или связанные записи недоступны. Ответ содержит {message}

404

Устав не найден

401

Пользователь не авторизован

403

У пользователя отсутствует право project_charter:manage

Система проверяет входные данные до поиска устава. Поэтому при некорректном теле запроса она может вернуть 400, даже если устав с указанным идентификатором отсутствует.
