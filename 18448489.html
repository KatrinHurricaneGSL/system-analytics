AVPM : PUT /api/tasks/{id}

Created by Перейти on нояб. 15, 2026

Обновляет редактируемые данные задачи, включая исполнителей, зависимости, трудозатраты и связанные материалы.

Доступ: JWT и разрешение kanban:edit_card.

Используется в UC-5. Редактирование задачи.

Схема работы

Алгоритм

  1. Проверить JWT, разрешение kanban:edit_card и входные данные. Найти задачу по идентификатору id.

  2. Обновить название, описание, срок выполнения, приоритет и остальные редактируемые свойства задачи.

  3. Заменить список исполнителей значениями из memberIds. Неизвестные идентификаторы пользователей не включать в результат.

  4. Заменить список необходимых задач значениями из requiredTasks. Удалить дубликаты и ссылку задачи на саму себя. Проверка циклических зависимостей не выполняется.

  5. Отдельно сохранить плановые и фактические трудозатраты, затем обновить связи со статьями базы знаний.

  6. Если isFunctionalRequirement=true, сохранить нормативные требования из regulatoryRequirementIds. В противном случае очистить существующие связи с требованиями.

  7. Синхронизировать матрицу нормативных требований проекта и записать действие обновления.

  8. Вернуть 204 без тела ответа.

Входные параметры

Параметр пути (PATH) и тело запроса (BODY, JSON).

Ответ

Ошибки

Код

Причина

Ответ

400

Некорректные входные данные

Стандартная ошибка валидации

Следующие ситуации могут вызывать исключения, которые контроллер не преобразует в отдельные предметные HTTP-ответы:

  • Задача не найдена.

  • Связанная статья базы знаний отсутствует или удалена.

  • Нормативное требование архивировано.

  • Проект доски не найден.

  • Нарушена целостность внешних ключей зависимостей.

Пример запроса

PUT /api/tasks/201
Content-Type: application/json

{
  "title": "Подготовить испытания",
  "description": "Уточненный план",
  "memberIds": [10],
  "requiredTasks": [202],
  "dueDate": null,
  "priority": 2,
  "plannedHours": 8,
  "actualHours": 2,
  "includeInCalendar": false,
  "isFunctionalRequirement": false,
  "knowledgeArticleIds": [],
  "regulatoryRequirementIds": []
}

При успешном обновлении сервер возвращает 204 No Content без JSON.
