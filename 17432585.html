AVPM : POST /api/project-charters/{id}/submit

Created by Перейти, last modified on нояб. 14, 2026

Отправляет устав на согласование по заданному маршруту.

Доступ: право project_charter:approve.

Используется в UC-4. Отправка на согласование.

Схема работы

Алгоритм

  1. Проверить, что комментарий не пустой и не состоит только из пробелов. Удалить пробелы в начале и конце текста.

  2. Найти устав по идентификатору. Проверить наличие хотя бы одного шага согласования и убедиться, что устав не имеет статус submitted.

  3. Очистить предыдущие решения и даты согласования. Присвоить первому шагу статус in_progress, остальным шагам статус waiting.

  4. Присвоить уставу статус submitted, увеличить версию, сохранить его состояние в истории версий и добавить в журнал события submitted и step_started.

  5. Вернуть обновленную карточку устава. Почтовые уведомления при отправке не создаются.

Входные параметры

Параметр пути (PATH) и тело запроса (BODY, JSON).

Где

Поле

Тип

Обязательно

Описание

PATH

id

integer

Да

Идентификатор устава

BODY

comment

string

Да

Непустой комментарий. Пробелы в начале и конце удаляются

Ответ

200 OK: возвращает обновленную карточку устава со статусом submitted и первым активным шагом согласования.

Структура ответа совпадает с GET /api/project-charters/{id}.

Ошибки

Код

Причина

400

Комментарий отсутствует или состоит только из пробелов, маршрут согласования пуст или устав уже имеет статус submitted. Ответ содержит {message}

404

Устав не найден

401

Пользователь не авторизован

403

У пользователя отсутствует право project_charter:approve

При ошибках проверки состояние устава остается без изменений.

Повторная отправка устава со статусами approved и rejected разрешена. При этом система сбрасывает предыдущие решения и запускает маршрут согласования заново.

Пример запроса

POST /api/project-charters/101/submit
Content-Type: application/json

{
  "comment": "Готово к согласованию"
}
